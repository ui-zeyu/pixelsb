# pixelsb

像素级图像查看器，面向 CTF 的位平面分析与 LSB 隐写提取：任意组合通道位查看画面与数值，用操作按配方逐层改造像素，把所选位拼成字节流。

窗口布局：左侧栏是配方（一条条操作叠成的栈）、中间画布、右侧栏与最右侧的按钮竖条 — 竖条上的按钮切换右侧栏的页面（`▦` 提取、`ⓘ` 文件信息）。

## 运行

```bash
uv run pixelsb
uv run pixelsb image.png
```

## 功能

- **配方（操作栈）** — 左侧栏自上而下是叠在原图之上的操作：每条一个开关、一个 `＋` 添加（只列不用带参数的反相、灰度、裁剪）、`▲` `▼` 调序、`✕` 删除，最底下的「原图」是文件里解码出来的像素，不能移动也不能关闭；点击列表外的空白处取消选中。操作自下而上依次作用，每条读到的是它下面所有操作留下的值——所以放在阈值之上的区域操作比较的是二值化后的值，放在位选择之上的读到的是选中位的值。画布、像素读数、提取流读的是同一份结果：加一条操作，画面和字节流同时变。
  - **位选择** — 画面画哪些位、提取流打包哪些位；在右侧「提取」栏的位网格里勾选（行首、列首复选框选整行/整列，⌘、Ctrl 或 Shift 加单击只看这一位），标题旁两侧 `◀` `▶` 按矩阵阅读顺序（R7…R0、G7…G0、B7…B0）逐位看单个位平面、`▲` `▼` 遍历整条通道，「原图」「全部最低位」是两个预设。位选择是替换关系：同时开着多条时只有最上面那一条算数（被替换的那一条会标明这点），位网格、快捷键与命令输入写的都是同一条。没有位选择操作时画面就是原图；按 R、G、B、A、1–9 或 `[` `]` 会自动补上一条。
  - **区域** — 按表达式只留下通过的像素：没通过的像素在画布上淡化（淡化只是观看效果，不写进导出的文件），提取流跳过它们，但**它们仍在画布上、仍可读数**——光标移到淡化像素上照样给出数值并画出光标框，只有被「裁剪」裁掉的格子在画布上真的看不见、也才没有读数。
  - **裁剪** — 画布收缩到命中像素的范围：`grid` 得到等步长子图、`rect` 得到裁剪。它只决定画布怎么摆，提取流本来就只读命中的像素，所以字节不变。
  - **反相 / 灰度 / 阈值 / 异或** — 值域操作：每个通道按所在通道的满值取反、三个颜色通道都换成亮度、按 值>阈值 压成满值或 0、与常数按位异或（阈值与异或的上限是该图通道的满值，8 位即 255、16 位到 65535）。它们改的是数据，像素读数与提取流都跟着变；灰度之上放阈值就是黑白二值化。「导出」把位选择与值域操作的结果存为图像文件。
  - **Alpha 通道** — PNG 的 RGBA / LA / 调色板带 alpha / **tRNS 颜色键**（真彩或灰度图用 tRNS 指定一个透明值，载入时补出一个 `A` 平面）、以及解码成 RGBA 的其它格式，都以 `A` 为一个普通通道载入：位网格里有它的一行、命令里写 `a`（或 `a.0`）、快捷键 `A` 选它的最低位、区域表达式里可以比较它、提取流按所选位把它一起打包。**画面**上选中 alpha 的位时，颜色合成到棋盘格上（alpha 0 全透、255 不透明），这是观看效果，和区域淡化同一原则——**导出的文件保留 alpha 通道**（写成 RGBA），不会把棋盘格印进像素；文件信息页把某个块渲染成像素时同样保留 alpha。
- **命令输入（`⌘F`）：所有操作的命令行，一行一个操作** — 选中一条操作时框里就是它的命令，改完回车原地替换（种类也可以换）；框为空时输入会在最上面添加；点击配方的空白处取消选中后框也是空的。**Esc 分两步**：框里有文字时只清空文字、不动任何操作（焦点留在框里），框已经是空的时候才删掉正在编辑的这一条并回到画布。**Shift+回车**则把这一行当作新操作加到栈顶（不动正在编辑的那一条），想连着叠几条时不必先用鼠标点空白处取消选中。**打字过程中不预演，回车才应用**（一条命令可能要重绘整幅图，写了一半的句子也不是命令；改了内容会清掉红边与状态栏的报错，但栈不动）。回车后框里的文本会被写成这条操作的标准写法——`b>r` 显示为 `b > r`、`xor 0xff` 显示为 `xor 0xFF`、通道按图像的顺序排列（`b or g` 写成 `g or b`）——所以框里和配方里那一条读起来完全一致；写了一半的句子与被拒绝的命令保持原样，等改好再回车。`＋` 菜单因此只列免参数的三种。

命令分三类，**一行的第一个词决定它属于哪一类**：

| 命令 | 类别 | 作用 |
| --- | --- | --- |
| `thr 128` | 操作命令 | 值 > 128 压成满值或 0 |
| `xor 0xFF` | 操作命令 | 每个通道与常数按位异或 |
| `inv` | 操作命令 | 每个通道按满值取反 |
| `gray` | 操作命令 | 三个颜色通道换成亮度 |
| `crop` | 操作命令 | 画布收缩到命中像素的范围 |
| `b.0` | 位选择 | 只看 B 通道的 bit 0（`r.0`、`g.7` 同理） |
| `b` | 位选择 | B 通道的全部 8 位 |
| `r or g.0` | 位选择 | 选择器之间用 `or` 取并、`and` 取交、`not` 取补（`all` 是全部位，如 `all and not r`） |
| `b > r` | 区域条件 | 按表达式过滤像素，见下一节 |
| `b > r and b > g` | 区域条件 | 区域条件之间照常用 `and` / `or` / `not` |
| `b > r and rect(0, 0, 10, 10)` | 区域条件 | 比较、坐标、`rect` / `grid` 都是同一种东西 |

**`and` / `or` / `not` 只在同类之间使用**，像强类型语言一样：`b > r and b.0` 这种把位选择和区域条件写在一起的命令会被拒绝并提示（它会指名两个操作），改成两行、按两次回车即可——操作之间的组合由配方栈负责，自下而上折叠。`b.0` 因此有两个身份但分界清楚：**整行只有通道与位 token** 时它是位选择；**同行里有比较 / 算术 / 坐标**时整行是区域条件，里面的 `b.0`（如 `B.0 == 1`）表示「该像素这一位为 1」。

落栈位置：命令框写的**就是它正在编辑的那一条**——框里显示哪条操作的命令，回车就把那一条改成新命令（换种类也行，位选择换成区域、区域换成阈值都算），**框不绑定任何操作时**（点了配方空白处、或手里那条没有命令）新命令加到栈顶；**Shift+回车**总是新增一条，不动手里的那条。位网格与快捷键是另一回事：它们只写位选择那一层（手里是位选择就改它，否则最上面那条，都没有就新增），所以点网格永远不会把区域或数值操作改写掉。**还没写完的行不落栈**：语法读不通（`b>r and b.`、`R >= `、`rect(1,`）时什么也不做，栈保持原样；语法读得通但运行期才失败的表达式（比如写错字段名）照旧先落栈，再由状态栏报错。数值只有两种写法：十进制 `128`，或带 `0x` 前缀的十六进制 `0x80`，且**不能超过这张图最宽通道的满值**（8 位图到 255，16 位图到 65535；越界会在改动发生前报错，因为那样的阈值只会让画面全黑、那样的异或会翻出通道装不下的位）。区域条件落栈时会按房内风格重写（`b>r and b>g` 显示为 `b > r and b > g`）。位网格与命令输入是同一份数据的两面：网格勾出的任何组合，框里都会出现对应的命令（每条通道整条写 `b`、单个位写 `b.0`，用 `or` 并列），反之输入命令网格立刻打勾；只有清空的位选择和别的图带过来的通道没有命令，框才留空。
- **帧导航** — GIF、APNG、WebP 的多帧在状态栏用 ◀ ▶ 切换，指示器显示帧序号与当前帧延时（帧间隔隐写的入口）；跨帧保留配方、位选择与缩放，某帧没有的通道自动不参与。
- **区域操作的表达式** — 类 Wireshark 表达式，画布淡化、提取流与通过计数共用：
  - `rect(50, 50, 100, 100)` 矩形，支持具名 `rect(left=, top=, right=, bottom=)`；
  - `grid(10, 20, 6, 6)` 从起点按步长跳跃取点（步长 1 即逐像素）；
  - 字段 `left` `top` `right` `bottom` 与各通道名，通道名取原始值，加位号取该通道的某一位（`R.0` 是最低位，`R.7` 是最高位），加 `.bits` 取勾选位算出的值；支持 `and` / `or` / 比较 / 算术。
- **画布选区（预览）** — 工具条「选区」工具下拖动框选：拖动与松开都只是预览，画布保留选区框、状态栏显示将写入的 `rect(...)`、尺寸与命中数，此时配方不变；回车把拖出的矩形作为新的区域操作加到栈顶，Esc 取消预览。按住空格临时平移。
- **提取面板** — 所选位按通道顺序、每个通道位从低到高拼成字节，每 8 位 1 字节；面板顶部三个控件切换读取顺序：通道排列（RGB / RBG / BGR …，只列参与提取的通道）、位序（先出现的位进字节最高位 MSB 还是最低位 LSB）、扫描顺序（XY 逐行 / YZ 逐列），默认是「原序 · MSB · XY」，切换后区域操作命中的像素同样按该顺序流入。整条 8 位通道全选时，LSB 得到的正是原始字节值（MSB 为按位反转的字节）。十六进制与文本分成两栏，文本栏表头显示当前编码（`ASCII ▾`），点击即可在 ASCII / UTF-8 / UTF-16LE / UTF-16BE 之间切换（多字节字符跨行时整字显示在结束它的那一行，只有真正非法的字节才显示替换符；被搜索隐藏的行不与相邻行拼接）；两栏各自独立选中复制（拖文本不会带上十六进制），支持按十六进制、ASCII 或偏移搜索。
- **提取流检测** — 提取面板顶部的检测条显示整条流的类型：[magika](https://github.com/google/magika) 的模型优先，模型对截断流失语或只猜成文本时由 [filetype](https://github.com/h2non/filetype.py) 的文件头签名兜底；流内的文件签名（PNG、JPEG、ZIP、RAR、7Z、PDF、GZIP、ELF…）与 flag 形态字符串（`flag{…}`、`CTF{…}`、`DASCTF{…}` 等）列成可点击标签：点击跳到对应行并选中字节，所在十六进制列着色（flag 为琥珀色、签名为蓝色）；「保存」把整条流（不受显示行数上限约束）写入文件。
- **文件信息** — 右侧栏第一页（菜单「文件 → 文件信息」同样会切到这一页），三张卡片：文件（名称、路径、格式与通道）、检查（块级清单：每行是单选框、偏移、块名、大小、必需/附属与行尾的一小段可打印文本预览——可打印字节照原样显示、其余显示为点，因此 iTXt/tEXt 的注释直接可读，拼在末尾的另一个文件也会以 `.PNG....` 之类的开头显形；IDAT 按 zlib 流编号归组，单个 IDAT 也算「流 1」、一条流跨多个块只算一组；结构异常以警告显示——拼接的第二个 IEND（Acropalypse，CVE-2023-28303）、假 IDAT（多出的数据流、超尺寸扫描行、流截断、IDAT 不连续）；文件正常时保持沉默。两个控件各管一件事：单选框是画布——每个可渲染单元一个单选框，即独立的块各一个、一条 zlib 流只在它的首块上一个（同流的其余块不再重复出现，靠「流 N」标注关联，因为它们在画布上是同一张图），选中它就把该单元渲染成像素（打开文件时画布显示的就是流 1，其首块默认处于选中态且不触发重新渲染），画布下方那行始终说明显示的是哪个流或哪一块，渲染失败就在同一行就地说明并把单选框退回画布真正显示的那一块；块名按钮是转储——点击后下方用提取面板同一个转储视图（同一控件、同样的偏移栏与字节标尺）展示该块，高度随内容伸缩，块头与 CRC 着色，标题条给出推测类型与可点击的 flag/签名标签；转储上方同样有一条搜索框，按十六进制、ASCII 或偏移过滤块内的行，语义与提取面板一致。清单里单选框所在的画布流那一行以强调色、正在转储的块以底色标出）、EXIF（基础 IFD 与 EXIF / GPS 子目录的标签）。
- **视图** — ⌘滚轮、触控板捏合或滑杆缩放，拖动平移，像素数值放大后直接画在格子里，`适配` / `1:1` 一键切换；菜单「视图 → 原图」清空全部操作、「全部最低位」把最上面那一条位选择换成每个通道的最低位（没有就加一条）。

快捷键见菜单「帮助 → 快捷键」。

## 开发

```bash
uv run ruff format
uv run ruff check
uv run ty check
uv run pytest
```

代码分三层：`domain/` 纯逻辑（模型与操作栈 `stack`、命令解析 `commands`、过滤器编译 `predicate`、位渲染、提取、字节转文本、检测与分类），`io/` 图像加载（含多帧）、容器检查、流分类器、写出，`ui/` Qt 界面（`layers` 图层面板、`canvas` 画布与选区、`extract_panel` 提取面板、`extract_view` 转储面板、`side_panels` 右侧栏竖条与页面切换、`info` 文件信息页、`painting` 绘制原语、`theme` 主题）。

操作栈是唯一的像素来源：`domain/stack.py` 把「图像 + 配方」算成一份 `Raster`（值、选中位、命中像素、来源坐标），画布、读数与提取流都从它读，所以一条操作同时改画面和字节。`stack.py` 的 `resolve` 只在栈变化时跑一次，窗口把它记在 `_raster` 里，移动光标不重算像素。

测试在 `QT_QPA_PLATFORM=offscreen` 下运行，不依赖真实显示：逐条用例覆盖领域与界面，`tests/test_properties.py` 另用 hypothesis 把过滤器语法、层叠裁剪与渲染丢给参考实现做属性校验。
