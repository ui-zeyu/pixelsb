# pixelsb

像素级图像查看器，面向 CTF 的位平面分析与 LSB 隐写提取：用操作按配方逐层改造像素，位选择也是其中一种操作，把画布上的位拼成字节流。规则只有一条——**每条操作都严格按照它下面那条操作的输出进行运算**。

窗口布局：左侧栏是配方（一条条操作叠成的栈）、中间画布、右侧栏与最右侧的按钮竖条 — 竖条上的按钮切换右侧栏的页面（`ℹ️` 文件信息、`📊` 直方图 · 卡方 · 频谱、`📤` 提取、`🔍` 扫描、`🐱` 猫脸变换爆破）。

## 运行

```bash
uv run pixelsb
uv run pixelsb image.png
```

## 功能

- **配方（操作栈）** — 左侧栏自上而下是叠在原图之上的操作：每条一个开关、一个 `＋` 添加（不用带参数的反相、灰度、裁剪、频谱，以及用对话框选图的「合成另一张图…」）、`▲` `▼` 调序、`✕` 删除，最底下的「原图」是文件里解码出来的像素，不能移动也不能关闭；点击列表外的空白处取消选中。操作自下而上依次作用，每条读到的是它下面所有操作留下的值——区域放在阈值之上比较的是二值化后的值，频谱接在位选择之后算的就是位平面的频谱，谓词读到的是投影后的通道。画布、像素读数、提取流读的是同一份结果：加一条操作，画面和字节流同时变。
  - **位选择（投影）** — 勾中的位压进各通道的低位端、通道位深随之收缩、没点名的通道退出画面，它是一道普通操作：`b.0` 让画布变成 0/255 的灰、读数是 0 和 1、提取流打包那一位、直方图只数 0 和 1，而它上面的阈值、频谱、猫脸读到的就是这张位平面图——**位平面上也能继续做 fft、阈值、猫脸**。在右侧「提取」栏的位网格里勾选（行首、列首复选框选整行/整列，⌘、Ctrl 或 Shift 加单击只看这一位），标题旁两侧 `◀` `▶` 按矩阵阅读顺序（R7…R0、G7…G0、B7…B0）逐位看单个位平面、`▲` `▼` 遍历整条通道，「原图」（把投影从配方里删掉）「全部最低位」是两个预设，快捷键 R、G、B、A、1–9、`[` `]` 与命令行 `b.0` 改的都是同一条投影层：网格与快捷键永远改写栈顶的投影，不在配方里叠塔。没有投影时画面就是原图；某帧没有的通道让投影报层错误（与频谱缺通道同一套失败语义）。提取流打包的是 raster 现有的每一位——**看什么就提什么**，通道顺序、位序、扫描序由下面的读取顺序决定。
  - **区域** — 按表达式只留下通过的像素：没通过的像素在画布上淡化（淡化只是观看效果，不写进导出的文件），提取流跳过它们，但**它们仍在画布上、仍可读数**——光标移到淡化像素上照样给出数值并画出光标框，只有被「裁剪」裁掉的格子在画布上真的看不见、也才没有读数。
  - **裁剪** — 画布收缩到命中像素的范围：`grid` 得到等步长子图、`rect` 得到裁剪。它只决定画布怎么摆，提取流本来就只读命中的像素，所以字节不变。
  - **反相 / 灰度 / 阈值 / 异或** — 值域操作：每个通道按所在通道的满值取反、三个颜色通道都换成亮度、按 值>阈值 压成满值或 0、与常数按位异或（阈值与异或的上限是该图通道的满值，8 位即 255、16 位到 65535）。它们改的是数据，像素读数与提取流都跟着变；灰度之上放阈值就是黑白二值化。「导出」把当前结果存为图像文件。
  - **频谱** — `fft` 把颜色与灰度通道（R、G、B、L）换成对数幅度谱（`numpy.fft`，直流居中、按各通道满值拉伸），远中心的亮点就是周期性图案；要点名参与通道就写 `fft r g`（只做这两条，`fft a` 只做 alpha），没点名的通道保持原值；阈值、裁剪可以照常接在它后面。
  - **合成（双图）** — `comb xor b.png` 把另一张图逐通道异或进来：按通道名对齐（都有的通道做异或、只有一方有的通道保持原样、位深取两侧较宽的一档），要同尺寸、至少一条同名通道，不满足就在命令框直接拒绝（与猫脸要方图同一套边界）。路径相对当前图所在文件夹解析，也可写绝对路径，文件读一次就记住。合成是一道普通操作：结果接阈值、fft、猫脸、扫描、提取都照常，三张图就是再叠一条 `comb`。`＋` 菜单的「合成另一张图…」用文件对话框走同一条路。
  - **猫脸变换** — `arnold 次数 a b` 按猫映射的**逆变换**重排像素（恢复方向）：与常见 arnold_encode/decode 脚本**同名同序**（矩阵作用在行、列上），出题方脚本里的参数直接填入即可还原。要方的样本矩形（裁成方图之后照样可以做），坐标从变换后的图重新算起。参数未知时用右侧栏的「猫」页爆破：按次数/a/b 的范围在后台线程遍历，候选边跑边以缩略图列出（结束后按平滑度重排），点击或用方向键选中一条就写成一条「猫脸变换」操作（画廊改写自己上一条，不会叠出一塔变换）。
  - **Alpha 通道** — PNG 的 RGBA / LA / 调色板带 alpha / **tRNS 颜色键**（真彩或灰度图用 tRNS 指定一个透明值，载入时补出一个 `A` 平面）、以及解码成 RGBA 的其它格式，都以 `A` 为一个普通通道载入：位网格里有它的一行、命令里写 `a`（或 `a.0`）、快捷键 `A` 选它的最低位、区域表达式里可以比较它、提取流按所选位把它一起打包。**画面**上选中 alpha 的位时，颜色合成到棋盘格上（alpha 0 全透、255 不透明），这是观看效果，和区域淡化同一原则——**导出的文件保留 alpha 通道**（写成 RGBA），不会把棋盘格印进像素；文件信息页把某个块渲染成像素时同样保留 alpha。
- **命令输入（`⌘F`）：所有操作的命令行，一行一个操作** — 选中一条操作时框里就是它的命令，改完回车原地替换（种类也可以换）；框为空时输入会在最上面添加；点击配方的空白处取消选中后框也是空的。**Esc 分两步**：框里有文字时只清空文字、不动任何操作（焦点留在框里），框已经是空的时候才删掉正在编辑的这一条并回到画布。**Shift+回车**则把这一行当作新操作加到栈顶（不动正在编辑的那一条），想连着叠几条时不必先用鼠标点空白处取消选中。**打字过程中不预演，回车才应用**（一条命令可能要重绘整幅图，写了一半的句子也不是命令；改了内容会清掉红边与状态栏的报错，但栈不动）。回车后框里的文本会被写成这条操作的标准写法——`b>r` 显示为 `b > r`、`xor 0xff` 显示为 `xor 0xFF`、通道按图像的顺序排列（`b or g` 写成 `g or b`）——所以框里和配方里那一条读起来完全一致；写了一半的句子与被拒绝的命令保持原样，等改好再回车。`＋` 菜单因此只列免参数的四种，另加用对话框选图的「合成另一张图…」。

命令分三类，**一行的第一个词决定它属于哪一类**：

| 命令 | 类别 | 作用 |
| --- | --- | --- |
| `thr 128` | 操作命令 | 值 > 128 压成满值或 0 |
| `xor 0xFF` | 操作命令 | 每个通道与常数按位异或 |
| `inv` | 操作命令 | 每个通道按满值取反 |
| `gray` | 操作命令 | 三个颜色通道换成亮度 |
| `crop` | 操作命令 | 画布收缩到命中像素的范围 |
| `fft` | 操作命令 | 颜色与灰度通道换成对数幅度谱（直流居中，按各通道满值拉伸）；`fft r g` 只做点名的通道：频域盲水印的入口 |
| `arnold 1 2 3` | 操作命令 | 按猫映射的**逆变换**重排像素（恢复方向），次数 a b（与常见 arnold 脚本同名同序）；要方的样本矩形 |
| `comb xor b.png` | 操作命令 | 与另一张图按通道名逐通道异或；要同尺寸、有同名通道，路径相对当前图 |
| `b.0` | 位选择（投影） | 只看 B 通道的 bit 0（`r.0`、`g.7` 同理）；一道普通操作，落进配方 |
| `b` | 位选择（投影） | B 通道的全部 8 位（保持原样的恒等投影） |
| `r or g.0` | 位选择（投影） | 选择器之间用 `or` 取并、`and` 取交、`not` 取补（`all` 是全部位，如 `all and not r`） |
| `b > r` | 区域条件 | 按表达式过滤像素，见下一节 |
| `b > r and b > g` | 区域条件 | 区域条件之间照常用 `and` / `or` / `not` |
| `b > r and rect(0, 0, 10, 10)` | 区域条件 | 比较、坐标、`rect` / `grid` 都是同一种东西 |

**`and` / `or` / `not` 只在同类之间使用**，像强类型语言一样：`b > r and b.0` 这种把位选择和区域条件写在一起的命令会被拒绝并提示（它会指名两个操作），改成两行、按两次回车即可——操作之间的组合由配方栈负责，自下而上折叠。逗号不算组合：Python 把 `b.0, b.1` 读成一组值（元组），整行会因此被拒绝，并列请写 `or`。`b.0` 因此有两个身份但分界清楚：**整行只有通道与位 token** 时它是位选择；**同行里有比较 / 算术 / 坐标**时整行是区域条件，里面的 `b.0`（如 `B.0 == 1`）表示「该像素这一位为 1」。

落栈位置：命令框写的**就是它正在编辑的那一条**——框里显示哪条操作的命令，回车就把那一条改成新命令（换种类也行，区域换成阈值都算），**框不绑定任何操作时**（点了配方空白处）新命令加到栈顶；**Shift+回车**总是新增一条，不动手里的那条。位选择行是唯一的例外：它命名的投影永远落在本层——改写栈顶已有的投影，没有就新建一条，无论框绑定着什么；位网格与快捷键改的也是同一条投影。**框只判这一行，栈才判这张图**：语法读不通（`b>r and b.`、`R >= `、`rect(1,`）时什么也不做，栈保持原样；整行不是一个条件时（逗号读成的一组值、方括号、`foo(1)` 这种没有的函数、`rect(0, 0)` 这种参数个数不对）也当场报错、输入的内容原样留在框里等改，绝不落栈成一条只会报错的操作；只有「条件写得没错、只是这张图给不出」的情况（字段名写错、位号超出通道、投影点名图上没有的通道）才会先落栈，再由状态栏报错。数值只有两种写法：十进制 `128`，或带 `0x` 前缀的十六进制 `0x80`，且**不能超过这张图最宽通道的满值**（8 位图到 255，16 位图到 65535；越界会在改动发生前报错，因为那样的阈值只会让画面全黑、那样的异或会翻出通道装不下的位）。区域条件落栈时会按房内风格重写（`b>r and b>g` 显示为 `b > r and b > g`）。位网格与命令输入是同一份数据的两面：网格勾出的任何组合，框里都会出现对应的投影命令（每条通道整条写 `b`、单个位写 `b.0`，用 `or` 并列），反之输入命令网格立刻打勾；只有别的图带过来的通道没有命令，框才留空。
- **帧导航** — GIF、APNG、WebP 的多帧在状态栏用 ◀ ▶ 切换，指示器显示帧序号与当前帧延时（帧间隔隐写的入口）；跨帧保留配方（投影也在其中，点名本帧没有的通道时报层错误）与缩放。
- **区域操作的表达式** — 类 Wireshark 表达式，画布淡化、提取流与通过计数共用：
  - `rect(50, 50, 100, 100)` 矩形，支持具名 `rect(left=, top=, right=, bottom=)`；
  - `grid(10, 20, 6, 6)` 从起点按步长跳跃取点（步长 1 即逐像素）；
  - 字段 `left` `top` `right` `bottom` 与各通道名，通道名取原始值，加位号取该通道的某一位（`R.0` 是最低位，`R.7` 是最高位）；支持 `and` / `or` / 比较 / 算术。
- **画布选区（预览）** — 工具条「选区」工具下拖动框选：拖动与松开都只是预览，画布保留选区框、状态栏显示将写入的 `rect(...)`、尺寸与命中数，此时配方不变；回车把拖出的矩形作为新的区域操作加到栈顶，Esc 取消预览。按住空格临时平移。
- **提取面板** — raster 各通道现有的位按通道顺序、每个通道从低到高拼成字节，每 8 位 1 字节；面板顶部三个控件切换读取顺序：通道排列（RGB / RBG / BGR …）、位序（先出现的位进字节最高位 MSB 还是最低位 LSB）、扫描顺序（XY 逐行 / YZ 逐列），默认是「原序 · MSB · XY」，切换后区域操作命中的像素同样按该顺序流入。投影只剩一条通道时列表只列它；整条 8 位通道全在时，LSB 得到的正是原始字节值（MSB 为按位反转的字节）。十六进制与文本分成两栏，文本栏表头显示当前编码（`ASCII ▾`），点击即可在 ASCII / UTF-8 / UTF-16LE / UTF-16BE 之间切换（多字节字符跨行时整字显示在结束它的那一行，只有真正非法的字节才显示替换符；被搜索隐藏的行不与相邻行拼接）；两栏各自独立选中复制（拖文本不会带上十六进制），支持按十六进制、ASCII 或偏移搜索。
- **提取流检测** — 提取面板顶部的检测条显示整条流的类型：[magika](https://github.com/google/magika) 的模型优先，模型对截断流失语或只猜成文本时由 [filetype](https://github.com/h2non/filetype.py) 的文件头签名兜底；流内的文件签名（PNG、JPEG、ZIP、RAR、7Z、PDF、GZIP、ELF…）与 `flag`/`ctf`/`key`/`password`/`secret` 关键字（不区分大小写）列成可点击标签：点击跳到对应行并选中字节，所在十六进制列着色（flag 为琥珀色、签名为蓝色）；「保存」把整条流（不受显示行数上限约束）写入文件。
- **扫描（zsteg 式全组合）** — 右侧栏 `🔍` 页把 zsteg 的参数空间一次扫完：通道组合（R、G、B、A 各自、`rgb`/`bgr`/`rgba`/`bgra`、灰度 `l`/`la`）× 公共位 × 位序（MSB/LSB）× 扫描序（XY/YZ），每个候选就是一次提取，在后台线程按当前画面的字节跑完——区域操作只让命中的像素进入字节流，和其他页面同源，命中判的就是它落栈后提取面板会显示的那条流。命中的（识别出文件类型或命中 `flag`/`ctf` 等关键字）排在前排并着色。**每个候选就是一次读取方式**：点击一行就把它的位选择写成栈上的投影、提取面板切到同一顺序，画布立即跟着变；换配方不清空命中列表，换图才清空，扫描可中止。
- **直方图 · 卡方 · 频谱** — 右侧栏 `📊` 页：上图把每个通道的值直方图叠在一张对数图里，值是栈留下的样本——投影打包后的整数也算数（`b.0` 后只有 0 和 1 两根柱），阈值、异或、频谱、猫脸之后的值算数，裁剪已生效，区域操作之后只数留下的像素（圈一块载荷再看分布，分布跟着变）；中间的卡方表按「通道 × 位」检验这些值的值对，p 接近 1 说明这一位像被按位写入过（值对计数被抹平），达标的位置以警示色标出，人口同样是区域留下的像素，列只列该通道现有的位（16 位通道列低 8 位）——一位的投影只剩一个值对，卡方无从检验，表格如实显示「—」；下方是当前操作结果的频谱：颜色各通道进各自的色槽、灰度铺满三槽（alpha 与 fft 命令一样不参与），直流居中，每通道按自身峰值拉伸，边长超过 512 取中间 512 参与——想看别的平面或位，用栈本身去选（位网格勾 `R.0`，频谱读到的就是那张位平面）。
- **文件信息** — 右侧栏第一页（菜单「文件 → 文件信息」同样会切到这一页），卡片：文件（名称、路径、格式与通道）、检查（块级清单：每行是单选框、偏移、块名、大小、必需/附属与行尾的一小段可打印文本预览——可打印字节照原样显示、其余显示为点，因此 iTXt/tEXt 的注释直接可读，拼在末尾的另一个文件也会以 `.PNG....` 之类的开头显形；IDAT 按 zlib 流编号归组，单个 IDAT 也算「流 1」、一条流跨多个块只算一组；结构异常以警告显示——拼接的第二个 IEND（Acropalypse，CVE-2023-28303）、假 IDAT（多出的数据流、超尺寸扫描行、流截断、IDAT 不连续）；文件正常时保持沉默。**宽高被篡改的 PNG**：解压后的数据量与声明的宽高对不上时，按数据量推算出所有正好放得下的 (宽, 高) 列成按钮（按与声明宽高比的接近程度排序），点击即修补 IHDR 写出副本并打开——声明尺寸偏大导致 PIL 拒绝打开的文件，载入时也会自动按最优候选修补（内存里修，磁盘文件不动）。两个控件各管一件事：单选框是画布——每个可渲染单元一个单选框，即独立的块各一个、一条 zlib 流只在它的首块上一个（同流的其余块不再重复出现，靠「流 N」标注关联，因为它们在画布上是同一张图），选中它就把该单元渲染成像素（打开文件时画布显示的就是流 1，其首块默认处于选中态且不触发重新渲染），画布下方那行始终说明显示的是哪个流或哪一块，渲染失败就在同一行就地说明并把单选框退回画布真正显示的那一块；块名按钮是转储——点击后下方用提取面板同一个转储视图（同一控件、同样的偏移栏与字节标尺）展示该块，高度随内容伸缩，块头与 CRC 着色，标题条给出推测类型与可点击的 flag/签名标签；转储上方同样有一条搜索框，按十六进制、ASCII 或偏移过滤块内的行，语义与提取面板一致。清单里单选框所在的画布流那一行以强调色、正在转储的块以底色标出）、**帧**（GIF 专有：每帧在画布上的实际尺寸、XY 偏移与延时列成表——帧间偏移隐写与「每帧尺寸隐写」的入口）、EXIF（基础 IFD 与 EXIF / GPS 子目录的标签）。
- **猫脸变换爆破** — 右侧栏 `🐱` 页：对当前画面的像素按次数/a/b 的范围遍历猫映射，读的就是画布所示的值（栈上有投影时，缩略图就是那张位平面图，置换与按位投影可交换，点进去画布即所见），候选边跑边以缩略图列出、结束时按平滑度重排；点击或用方向键选中写成一条「猫脸变换」操作，选中的缩略图带描边，方向键在画廊页代替画布移动光标；画廊改写自己上一条，换图才清空结果，搜索可中止。
- **视图** — ⌘滚轮、触控板捏合或滑杆缩放，拖动平移，像素数值放大后直接画在格子里，`适配` / `1:1` 一键切换；想回到解码原图，就把配方里的操作逐条 `✕` 删掉（投影用提取栏的「原图」预设删掉，其余操作同样逐条处理）。

快捷键见菜单「帮助 → 快捷键」。

## 开发

```bash
uv run ruff format
uv run ruff check
uv run ty check
uv run pytest
```

代码分三层：`domain/` 纯逻辑（模型与操作栈 `stack`、命令解析 `commands`、过滤器编译 `predicate`、扫描候选 `scan`、位渲染、提取、直方图与卡方 `histogram`、对数幅度谱 `spectrum`、字节转文本、容器审计 `container` 与它的容错块解码 `png_render`、检测与分类），`io/` 图像加载（含多帧）、容器检查、流分类器、写出，`ui/` Qt 界面（`layers` 图层面板、`canvas` 画布与选区、`extract_panel` 提取面板、`extract_view` 转储面板、`scan_panel` 扫描页、`arnold` 猫脸变换爆破画廊、`histogram_panel` 直方图页、`side_panels` 右侧栏竖条与页面切换、`keymap` 键盘映射、`worker` 扫描线程的启停、`info` 文件信息页、`painting` 绘制原语、`theme` 主题）。

操作栈是唯一的像素来源：`domain/stack.py` 把「图像 + 配方」算成一份 `Raster`（各通道样本、命中像素、来源坐标），画布、读数与提取流都从它读，所以一条操作同时改画面和字节。位选择是普通的一条操作：投影把勾中的位压进低位端并收缩通道位深，之后的一切——读数、直方图、提取流、再往上的操作——读到的都是投影后的样本。`stack.py` 的 `resolve` 只在栈变化时跑一次，窗口把它记在 `_raster` 里，移动光标不重算像素。

测试在 `QT_QPA_PLATFORM=offscreen` 下运行，不依赖真实显示：逐条用例覆盖领域与界面，`tests/test_properties.py` 另用 hypothesis 把过滤器语法、层叠裁剪与渲染丢给参考实现做属性校验。
